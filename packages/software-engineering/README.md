# Software Engineering Package

## 目标
先建立最小可解释模型，再修改真实系统。核心顺序：
`Claim → Model → Invariant → Counterexample → Decision → Evidence`。

## 主要资产
- `software-engineering-review`：真实软件工程任务的总入口。
- `project-recovery`：跨会话/机器/工作树恢复正确 frontier，而不是重扫历史。
- `invariant-driven-engineering-debugging` 位于 engineering 包：适合反复修不好的状态型故障。

## 触发
当任务涉及真实代码、运行时、部署、恢复、跨组件状态或完成声明时使用。
